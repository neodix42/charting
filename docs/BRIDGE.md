# CryptoDesk bridge v1

The local Wails v2 binding is generated from exported methods on `main.App`. The frontend's typed `bridge/api.ts` is an adapter over these generated browser globals; no HTTP server is used in the desktop release.

`LoadWorkspace()` returns `{workspace,revision,recovery}`. A nonempty recovery reason prevents mounting the workspace or saving defaults. `SaveWorkspace(expectedRevision,sessionId,editSequence,workspace)` validates the schema and semantics and returns `{revision,acceptedEditSequence}` after a FULL SQLite commit. Native window state is captured at commit.

`ListInstruments(exchange)` returns the public spot catalog. `AttachChart(chartId,generation,feedKey,fromSec,toSec)` returns `{leaseId,revision,bars,health}` immediately from the cache, and starts shared provider streams/history asynchronously. `DetachChart(leaseId)` is idempotent. `GetFeedSnapshot(leaseId,afterRevision)` provides a complete bounded snapshot; afterRevision is informational and snapshots can always repair a gap. `GetHistory(requestId,feedKey,fromSec,toSec,maxBars)` returns `{requestId,feedKey,bars,moreHistory}` with ascending UTC seconds. Limits are 1,000/request (Coinbase 350), 10,000/feed memory cache and 250,000 total in-memory cached candles. These RAM limits do not cap optional persistent candle storage.

Listen to `market:update` before attaching. Each update contains `leaseId,chartId,generation,feedKey,revision,kind,bars,health`. Apply the attach snapshot at revision R, then only newer buffered events. Revision gaps require a new snapshot. Events are revision-serialized; stale chart generations cannot apply to another instrument. Queue bounds force reconciliation.

`feedKey` is `{exchange,market:"spot",instrument,timeframe}`; `bars` contain `{time,open,high,low,close,volume,closed,quality,sourceRevision}`. `health` is `{state,reason,lastMessageAt,lastTradeAt}`, timestamps in seconds. Imported JSON never controls request URLs. Errors are safe readable strings prefixed with their classification where applicable.

Timeframes include `1w` (UTC Monday boundaries). Chart configuration optionally carries `indicators:[{id,type,parameters,color?,lineWidth?}]`; the backend validates it with the workspace and persists it without opening additional feeds. `lineWidth` is an optional integer from 1–4 for SMA/EMA only. Omitted widths render at two pixels and stay omitted on legacy round trips. Frontend calculations/rendering use the existing chart's candles. Weekly Coinbase history aggregates genuine daily candles rather than requesting an unsupported weekly granularity.

Workspace configuration optionally includes `chartRightGap:{unit:"bars"|"pixels",value:integer}`. The default is ten bars, including for legacy documents that omit the field. The backend validates whole values from 0–500 bars or 0–5,000 CSS pixels. Omission remains omitted on legacy round trips; new workspaces include the default explicitly. Applying a changed preference returns all saved chart views to live while retaining their spacing and price settings; only active-tab renderers update or fetch latest history. No additional feed lease or database migration is required.

A MACD indicator may also include `paneStretchFactor`, a finite number from 0.001 to 1,000 describing its height relative to the main price pane. The field is optional and rejected for other indicator types. Resizing captures all affected MACD ratios through the existing workspace save path; tab switches and normal close capture remaining changes. Restored renderers apply each ratio by indicator ID, independent of changing pane indexes.

Import/export use native file dialogs; import validation and confirmation precede a transaction with a bounded backup. Import/reset/recovery return a LoadWorkspace-shaped result. `GetBackups` lists safe recovery choices. `OpenTradingView` opens only the fixed HTTPS creator URL.

Local candle storage is a separate, machine-local profile preference, disabled by default. It is never a field in workspace JSON, and workspace import/export/reset do not alter it. Its bindings are:

- `GetCandleStorage() -> {enabled:boolean,directory:string,sizeBytes:integer,error?:string}` returns the applied configuration and current total regular-file size of the selected folder, without following symlinks. `error` exposes cache/open/measurement failures without pretending that storage is healthy.
- `ConfigureCandleStorage(enabled:boolean,directory:string) -> {enabled,directory,sizeBytes,error?}` normalizes the directory, opens the selected cache when enabled and commits both preferences before replacing the previously applied configuration. An empty/whitespace directory selects `<profile>/candles`. Rejection preserves the prior applied configuration. Reapplying the same configuration retries an unavailable cache. Successful enable/folder changes seed genuine candles already held in memory without adding market subscriptions.
- `ChooseCandleStorageDirectory() -> string` opens the native folder dialog and returns its selection, or `""` on cancellation. Choosing a folder does not apply it.

Preferences are stored in `<profile>/candle-storage.json`, with cache data in `<directory>/candles.sqlite3`. The default directory follows `--data-dir` or the normal profile: `$XDG_DATA_HOME/cryptodesk/candles` (normally `~/.local/share/cryptodesk/candles`) on Linux and the portable `data/candles` directory on Windows. Disabling retains files; changing directories retains the previous cache for later reuse. Accepted genuine live/history candles are queued for serialized writes, and shutdown drains accepted writes. Persistent disk usage can grow without automatic deletion; memory caches and queues retain their bounds.

A disk-backed attach can initially return health state `cached` with the reason `Locally stored candles; refreshing public spot data`. Public streams still connect. History bypasses a provider request only for a complete, contiguous page of closed past buckets; current/open buckets and gaps require provider data. Cached source revisions are reset for the new session so stale connection counters cannot block live corrections. Background disk failures emit `candle-storage-error` with a user-safe string message and remain available in storage information. The frontend displays the event, preserves the applied setting on configuration errors, and polls folder size about every five seconds only while enabled storage settings are visible. Late responses cannot replace newer edits or a newer applied configuration.

After subscribing to close/window events, the workspace calls `FrontendReady()`. Backend close requests received before DOM or workspace-listener readiness remain queued; a later mount can receive the pending request again. A `prepare-close` event includes the current close-request token. Frontend captures viewports, awaits autosave and calls `ConfirmClose(token,false)`; a failed save keeps the app open and supports retry or explicit discard. A ten-second timeout is failure, never success. `window:state` reports sampled changes in normal size/maximized state. Diagnostics describe actual adapter sockets, shared leases, queues, cache counts, revisions and frontend chart instances.

On Linux the command-line process supervises a GUI worker in a separate process group. Terminal Ctrl+C reaches the supervisor, which relays SIGINT only to the GUI PID, keeping WebKit processes alive for the existing frontend save acknowledgment. SIGTERM follows the same route. The supervisor returns the worker's exit status; it does not open the workspace. A readiness pipe protects startup interrupts, and a reusable worker signal listener supplements Wails' one-shot listener. After final acknowledgment, cancel window sampling before quitting the toolkit main loop, then close market services and SQLite. No signal timeout automatically discards a draft.
